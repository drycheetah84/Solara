# Known issues, preserved original defects, and deliberate deviations

Legend: **PRESERVED** = original behaviour reproduced on purpose (fixing it would change the
contract); **DEVIATION** = Solara differs, with the reason; **ENV** = environmental limitation.

## Hosting / framework

| ID | Kind | Description |
|---|---|---|
| HOST-001 | PRESERVED | A route that exists only for another HTTP method answers **404**, not 405 (`FindMatchingEndpoint` filters by method; `MethodNotAllowed` is unreachable). |
| HOST-002 | DEVIATION | Original never shut down (`Task.Delay(-1)`, killed by the OS). Solara also stops servers and closes the database on SIGINT/SIGTERM. Additive; no contract change. |
| HOST-003 | PRESERVED | A query string containing a segment without `=` (e.g. `?flag`, or a trailing `&`) makes any handler that reads queries fail with a 500 page (`ArgumentNullException`, null dictionary key). |
| HOST-004 | PRESERVED | `JsonBody` without a `Content-Type` header → 500 (`NullReferenceException`); non-JSON content type → 500 (`InvalidOperationException`). |
| HOST-005 | DEVIATION | 500 pages contain the .NET exception type and message but **not the stack trace** (`ex.ToString()` included server-internal frames). Normalised in differential tests. |
| HOST-006 | DEVIATION | Original: an `OPTIONS` request (or any second write) after a preprocessor already wrote a response tried to set the status after headers were sent, which threw inside the catch block and **terminated the listener loop** (the server stopped accepting requests). Solara writes the first response only and keeps serving. Reproducing a remote-triggerable outage is not a compatibility requirement. |
| HOST-007 | PRESERVED | Responses written by a stopping preprocessor carry **no CORS headers** (CORS is added after the preprocessors run). |
| HOST-WS-001 | DEVIATION | If a server's WebSocket hook declines a request, the original left the connection open forever; Solara closes it. |
| HOST-SC-001 | PRESERVED | `HttpStorageContainerProcessor` (registered by no server): upload/delete always 400 ("Container name is required." — `JsonElement is string` is never true); create/delete with a `name` → 500 (`InvalidCastException`); downloads never match (`Uri.Split('/')` has 3 parts for `/a/b`). |
| HOST-MIME-001 | DEVIATION | `MimeTypeMapOfficial` has ~600 extensions; Solara's table covers the web-relevant subset; unknown → `application/octet-stream` as before. Only used by the (unregistered) static-file/storage preprocessors. |
| HOST-HDR-001 | DEVIATION | HttpListener added `Server: Microsoft-HTTPAPI/2.0` (Windows) / Mono header (Linux); Go's server sends no `Server` header. Not part of any client contract. |
| LOG-001 | DEVIATION | Log lines show thread id `1` (Go has no stable OS thread ids); the file sink's caller-info segment renders empty, as it effectively did in the original (enricher filtered on an `Astra.` assembly prefix that no assembly matched). |
| DI-001 | PRESERVED | DI quirk: a class with constructor parameters registered with a pre-built instance never resolves (instance stays null). The original hit this for `AstraDatabaseManager`/`AstraDatabase`; servers use the static `Program.Database`. |

## Persistence

| ID | Kind | Description |
|---|---|---|
| DB-001 | DEVIATION | Storage engine is bbolt (`<name>.solara.db`) instead of LiteDB (`<name>.db`); LiteDB files are never opened by Solara. Migrate with `tools/litedb-export` + `solara import-litedb` (docs/DATA_MIGRATION.md). Collection names, member names, `_id` values/order and value semantics are unchanged. |
| DB-002 | DEVIATION | Encryption at rest: AES-256-GCM with a PBKDF2-SHA256 key from the same configured password (LiteDB used its own AES scheme). File format differs by necessity; the protection property is preserved. |
| DB-003 | PRESERVED | LiteDB predicate queries compare strings case-insensitively (default collation `en-US/IgnoreCase`, verified with the original runtime), while LINQ over `FindAll()` is case-sensitive. Solara reproduces both, per call site. |
| DB-004 | PRESERVED | Dates read back from storage have millisecond precision and `Kind=Local`, so JSON shows the server's local offset (e.g. `+00:00` on a UTC VPS) for stored dates and `Z` for fresh `UtcNow` values. |

## Security notes (original behaviour, not changed)

| ID | Kind | Description |
|---|---|---|
| SEC-001 | SUPERSEDED (SEC-F6) | HalcyonSocket agent protocol (:9100) was unauthenticated in the original; Solara adds optional agent auth (strict with `SOLARA_REQUIRE_AGENT_AUTH=1`). Keep :9095/:9100 firewalled anyway. |
| SEC-002 | DEVIATION (hygiene) | Secrets the original hard-coded in C# are read from `config/legacy-secrets.env` / `SOLARA_<NAME>` env vars with the **same values** (generated by `tools/scripts/extract-legacy-secrets.sh`). `solara serve` refuses to start while any of them is missing (an empty key could otherwise match an empty header and fail open). |

## Persistence (continued)

| ID | Kind | Description |
|---|---|---|
| DB-005 | PRESERVED | LiteDB BsonMapper defaults (`TrimWhitespace`, `EmptyStringToNull`): stored strings are trimmed and `""` reads back as `null` (also list elements / dictionary values). Visible in JSON (e.g. default roles show `"role_description":null`) and in lookups (a `""` key never matches a stored record, so e.g. title-data with key `""` inserts a new row each time). Verified against LiteDB 5.0.21 for all 47 persisted models. |
| DB-006 | DEVIATION | `Dictionary<string,…>` members serialize with keys **sorted** (Go maps) instead of insertion order. Values and key sets are identical; 10 of 597 differential steps differ only in key order (e.g. station config served to the game-server DLL). JSON object order is not semantically significant to the known clients. Stored-model data is unaffected. |

## Environment / verification limits

| ID | Kind | Description |
|---|---|---|
| ENV-001 | ENV | `go test -race` could not run: no C compiler on this machine (cgo disabled). Concurrency is covered by design (per-server mutex, mutex-guarded statics) and repeated test runs, not by the race detector. |
| ENV-002 | ENV | The original servers could not bind their privileged `http://+:port/` prefixes (no elevation/URL ACL), so differential testing ran the original **in-process** (HttpListener neutralised, real routing/binding/handlers). The listener loop itself was compared by code review + Go tests, not by wire capture. |
| ENV-003 | ENV | Live external services were not exercised: Meta graph API (attestation/nonces/bans), the deployed game-server DLL, the PowerShell allocator agent on a Windows box, and production LiteDB data. Each has a protocol-level test (fake Meta server; agent protocol replay vs the .NET oracle; LiteDB fixture import). |
| DEPLOY-001 | OPEN | `install.sh` / `install.ps1` / `Redeploy-Vps.ps1` still build and register the .NET backend. Solara deployment steps are documented (docs/BUILD_AND_DEPLOY.md) but the scripts were not rewritten. |
| HOST-009 | BLOCKED (authorization) | `AstraWebSocketServer` (+ route attributes/state machine) has no subclass anywhere in the original, i.e. it is unreachable; it was not ported. Per CLAUDE.md §3.1 dropping it needs explicit user authorization — port on request. |

## Security hardening (deliberate deviations, applied after the security review)

| ID | Kind | Description |
|---|---|---|
| SEC-F1 | FIXED (port-introduced) | **EOS player-data path traversal.** Go did not remove `.`/`..` path segments the way HTTP.sys / `System.Uri` did, so route parameters could carry `..` into file paths (read/write outside `playerdata/`, e.g. `config/legacy-secrets.env`). Fix: `hosting.CanonicalizePath` resolves dot segments (also `%2e`, backslashes) for every server — restoring original routing — plus a component and containment check in `internal/eos/gateway_playerdata.go`. Test: `internal/eos/playerdata_traversal_test.go` (raw-socket attacks). |
| SEC-F2 | FIXED (original defect, contract change) | **Unauthenticated A2StationDb (:78).** The original let anyone mint an API key for any user, change roles, delete users/stations or rewrite config. `internal/ares/a2station_auth.go` now requires: *admin tier* (16 routes: key minting, users, roles/permissions, bans, station/deployment deletion) — master key (`x-api-key`), game-server key (`x-server-api-key`), or a user key whose user has `admin` on that station or globally; *writer tier* (16 routes: station/deployment/event writes, config, server events, signups) — any key this backend issued (master/server key, login-minted user key, deployment key). Denials: 401 `{"error":"unauthorized"}`. Unchanged/open: logins, reads, `register_server`, `update_player_count`, `server_heartbeat`, spec-level routes, drafters feed, board images. **Operational impact:** any tooling or client that called the guarded routes without `x-api-key` must now send one (the docs' curl examples already send the master key; the native client sends its login key). Test: `internal/ares/a2station_auth_test.go`. Differential: the anonymous sweep now differs from the original on exactly the 32 guarded routes (+2 reads whose data came from those writes). |
| SEC-F4 | FIXED (port-introduced) | **Single slow client stalls a server.** Bodies are now read before the per-server lock with a 2-minute deadline and a 64 MiB cap (413 above it; stalled uploads are dropped without a response, as HTTP.sys did); responses get a 2-minute write deadline; idle keep-alives close after 2 minutes. Per-request deadlines are used so WebSocket connections are unaffected. Test: `internal/hosting/slowclient_test.go`. |
| SEC-OPEN | OPEN | Not yet addressed (await decision): F7/F8 Mothership data exposure / cross-player deletion, L1–L5. Game-server ingest routes on :78 remain open in compat mode (strict mode: SEC-SID-0). F5/F6: see SEC-F5/SEC-F6. |
| SEC-DASH-1 | HARDENED | Dashboard brute force: after 10 failed credential attempts within 5 min from one socket peer, `/api/*` answers 429 `{"error":"too many failed attempts"}` for 15 min (even with a correct key). Keyed by the TCP peer, not the spoofable `Cf-Connecting-Ip`/`X-Real-Ip`; requests carrying no credential are not counted. A reverse proxy in front makes all clients share one peer address — the Next.js proxy always sends the right key, so it is unaffected. |
| SEC-DASH-2 | HARDENED | Every :8080 response carries `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; `/api/*` adds `Cache-Control: no-store`; `/` adds a Content-Security-Policy. (Differential tests show these as the only differences on the dashboard sweeps.) |
| SEC-DASH-3 | HARDENED | A generated `DASHBOARD_ADMIN_KEY` / `DASHBOARD_SESSION_SECRET` (when unset) is written to `config/generated-<name>.txt` (0600) instead of being printed to the console/journal; only the path is logged. |
| SEC-DASH-4 | HARDENED | Startup warnings when `DASHBOARD_AUTH_ENFORCE=0` (API open), when `DASHBOARD_ADMIN_KEY` is shorter than 24 chars, and when the dashboard listens on all interfaces. |
| SEC-DASH-5 | NEW OPTION | `DASHBOARD_BIND_ADDRESS` (e.g. `127.0.0.1`) restricts the :8080 listener; default unchanged (all interfaces). |
| SEC-DASH-6 | FIXED (original F3) | Stored XSS in the embedded dashboard page: every server value is HTML-encoded (`esc`), handler arguments use `jsArg`, image/link URLs are limited to http(s)/same-origin (`safeUrl`), path IDs are percent-encoded; the admin key moved from `localStorage` to `sessionStorage` (old copies are deleted). |
| SEC-DASH-7 | HARDENED | `/auth/meta` SSO callback log: OAuth values (`code`, `token`, `state`, …) are redacted and CR/LF neutralised (log injection). |
| SEC-SID-0 | FIXED (original design, contract addition) | **Static shared game-server keys replaced by per-server identity tokens** (`internal/serverid`, docs/SERVER_IDENTITY.md). Spin-ups mint an `sst1_` token bound to the deployment/box (+station from the dashboard) and pass it as `-ServerApiKey`/`-DashboardApiKey` (+ `server_token` field); hash-only storage; idle/absolute expiry; revoked when the server exits, is taken offline, the watchdog gives up or the deployment is deleted. Accepted wherever the static keys were (Mothership trusted-server/IsAdmin, :78 guard, `log_in_with_key`, spec-level check, board upload; NOT purge/prune). On :78 a token is bound: naming another deployment/station → 403 `{"error":"forbidden"}`. Static keys: compat (default) accepted + hourly deprecation warning per route; `SOLARA_REQUIRE_SERVER_TOKENS=1` rejects them and makes ingest routes require a token. Dashboard: `GET /api/server-tokens`, `DELETE /api/server-tokens/{id}` (after the 53 original routes). CLI: `solara server-token …` / `agent-token …`. Tests: `internal/serverid`, `internal/mothership/serverid_auth_test.go`, `internal/ares/serverid_auth_test.go`, `internal/halcyonsocket/security_test.go`. |
| SEC-SID-1 | RISK (unverified) | Whether the DLL sends `x-api-key`/`x-server-api-key` on `register_server`/`update_player_count`/`server_heartbeat` is unknown; strict mode requires a token there. Verify with a capture before enabling `SOLARA_REQUIRE_SERVER_TOKENS`. |
| SEC-SID-2 | OPERATIONAL | Unreal's FParse uses the FIRST occurrence of a flag and agents put their base args first, so a static `-DashboardApiKey`/`-ServerApiKey` left in `agent.cfg` `game_args` / `server.config.psd1` overrides the per-server token (the server keeps using the static key in compat mode, and fails in strict mode). Remove them; `deploy/windows/HalcyonAgent.ps1` drops them automatically when a spin-up carries a token. The compiled agent must be reconfigured by hand. |
| SEC-SID-3 | FIXED | A server token now qualifies for :78 **admin** routes only when the route targets the token's own station; station-less admin routes (minting user API keys, user create/update/delete) refuse server tokens (401). Writer routes remain usable within the token's deployment/station binding. Test: `TestA2ServerTokenAdminScope`. |
| SEC-SID-4 | OPERATIONAL | `solara serve` holds the database lock: the token CLI only works while the server is stopped (10 s timeout message); while it runs use `GET/DELETE /api/server-tokens`. Tokens expire after `SOLARA_SERVER_TOKEN_MAX_DAYS` (30) even while a server runs. |
| SEC-F5 | FIXED (original F5) | **Spin-up argument injection / unauthenticated :9095.** All 5 :9095 routes require the dashboard admin key (`x-dashboard-key`) or `ServerMasterKey` (`x-api-key`, compat only) → 401 `{"error":"unauthorized"}` (no local tooling of the original called :9095). `RequestSpinUp` validates map/region/box/name charsets and every arg token (`-Flag` / `-Key=Value`, max 32) against a denylist (ExecCmds, exec, dpcvars, run, abslog, log=, userdir, *ini, key/identity flags, backend/mothership host overrides); callers can no longer supply `-DashboardDeploymentId`. Rejection uses the usual SpinUpResult error shape. Test: `internal/halcyonsocket/security_test.go`. |
| SEC-F6 | FIXED (original F6, supersedes SEC-001) | **Unauthenticated agent protocol :9100.** 64 KiB line/buffer cap (disconnect); optional agent token in `hello` (Kind agent, bound to the box; re-validated on heartbeat); `SOLARA_AGENT_ALLOWED_IPS`; `SOLARA_REQUIRE_AGENT_AUTH=1` disconnects agents with neither (compat: warning); box-name hijack refused unless token holder (evicts the old connection) or same IP; `spunup`/`exited` about launches the hub sent accepted only from the launcher (same connection/IP/token). Residual in compat mode: an unauthenticated agent can still report high capacity and win spin-ups, and can claim a box name that is currently disconnected — enable strict mode. Compiled agent: works unchanged (use the IP allowlist). |
